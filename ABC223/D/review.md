# ABC223 D — Restricted Permutation

- 問題: https://atcoder.jp/contests/abc223/tasks/abc223_d
- 状態: **AC（本人確認済み）**。重複辺の修正後にAC。
- 最終ACコード: [main.cpp](main.cpp)（修正前の試行錯誤は [draft.cpp](draft.cpp) と [memo.txt](memo.txt) に記録）
- 試行錯誤: [memo.txt](memo.txt)

## 発想

各条件 `A_i` が `B_i` より先に来ることを有向辺 `A_i -> B_i` に対応させる。
これはトポロジカルソートである。各ステップで前提条件の残っていない（入次数0）頂点のうち番号最小を選べば、辞書順最小の順列になる。最後に全頂点を取り出せなければ、有向閉路があり不可能。

## 初版とTLE

各頂点の前提条件を `set` で管理し、未処理の頂点全体を毎回走査して選べる最小頂点を探していた。
同じ検索を繰り返すため最悪二次時間となり、**12 AC / 10 TLE**。

## 2版とWA/TLE

入次数0の頂点を `priority_queue<..., greater<...>>` へ入れ、最小のものを取り出す方法に改善した。方向性は正しいが、**11 AC / 8 WA / 3 TLE**。

重複辺 `A -> B` が入力されると、`E[A]` には `B` が複数回入り、`edge[B]` はsetなので `A` を一度だけ保持する。
次のコードでは同じ頂点を繰り返しキューへ追加してしまう。

```cpp
edge[i].erase(e);
if (edge[i].empty()) S.push(i);
```

重複投入があると誤った重複出力でWAになるだけでなく、重複処理が連鎖してTLEになり得る。

## 修正後のACコード

```cpp
if (edge[i].erase(e) && edge[i].empty()) S.push(i);
```

`set::erase(key)` が削除した要素数を返すことを利用する。実際に前提条件を削除し、ちょうど入次数0になったときのみ候補へ追加する。
修正後は各頂点を高々一度処理し、全体の計算量は **O((N+M) log(N+M))** 程度、空間は **O(N+M)**。

より簡潔な実装は、`set` の代わりに `indegree[v]`（入次数）を持つKahnのアルゴリズム。重複辺も複数本として数えて同じ回数減らせば正しく扱える。

## 振り返り

グラフへの帰着・辞書順最小の貪欲法・優先度付きキューへの改善は自力。データ構造を変更しても「各頂点が一度だけ候補に入る」という不変条件を保証する必要がある。
修正版のACを確認し、`main.cpp` に保存した。今回の重要な学びは、優先度付きキューに同じ頂点を重複投入しないという不変条件を守ること。
