## コンテスト時の解法: 左方向への全探索

各位置 `i` について `j=i-1,i-2,...,0` の順に調べ、初めて `A[j]>A[i]` を満たす `j` があればその1-indexed位置 `j+1` を出力する。存在しなければ `-1`。

右から左の順で調べているので、最初に条件を満たす位置こそ最も近い位置。先頭 `i=0` は左側がないため `-1`。

- 時間計算量: **O(N²)**（最大 `N(N-1)/2` 回の比較）
- 空間計算量: **O(N)**（入力配列。探索部分の追加領域は O(1)）

`N<=100` という制約では、最大4950組の比較だけで済む。単調スタックが思いつかなくても、全探索を選んだコンテスト中の判断は合理的。

## 復習: 単調スタックによる O(N) 解法

未処理の将来の位置に対して候補となり得るインデックスを、**身長が下がる順**に `vector<ll> st` で管理する。

```cpp
vector<ll> st;
rep(i, N) {
    while (!st.empty() && A[st.back()] <= A[i]) {
        st.pop_back();
    }
    cout << (st.empty() ? -1 : st.back() + 1) << '\n';
    st.push_back(i);
}
```

### なぜ削除してよいか

左の位置 `j` より右に `k` があり、`A[j]<=A[k]` なら、**今後 `j` が答えになることはない**。
今後のある位置 `i>k` に対して `j` が条件 `A[j]>A[i]` を満たすなら、`k` も `A[k]>=A[j]>A[i]` を満たし、しかも `k` の方が近いから。

そのため現在の高さ `A[i]` 以下の候補を末尾からすべて取り除いてよい。残った候補の最も右側（スタック末尾）が答えである。

**`<` ではなく `<=` を使う理由:** 求めるのは `A[j] > A[i]` という**厳密不等号**であり、同じ高さは候補にならないため。

### 計算量と償却解析

各インデックスは `push_back` されるのが1回、`pop_back` されるのが高々1回。内側が `while` であっても、全体のpush/pop回数は高々 `2N` 回。よって時間 **O(N)**、スタックの追加空間 **O(N)**。

## 自力の気づき・振り返り

- 本番では線形解法を思いつかなかったが、制約を見て安全な全探索を採用し、**7:59・WAなし**でACした。
- 復習で「右側に身長5があれば、左側の身長3が選ばれることはない」と**候補を破棄できる根拠**を自力で説明できた。
- `<=` の理由を `A[j]>A[i]` という条件から正しく指摘できた。
- 学び: 「二重ループだから O(N²)」とは限らず、要素ごとの出し入れの総数を数える **償却解析**で O(N) と分かる。
- 同型問題では「より右にいて、値が同等以上なら左の候補を永久に捨てられるか」を検討すると単調スタックにつながる。
