# ABC485 C — Different Neighbor

- [問題文](https://atcoder.jp/contests/abc485/tasks/abc485_c)
- コンテスト結果: **AC / 300点 / 19:23 / WAなし**
- [main.cpp](main.cpp): 本人のコンテスト中のACコード（コメントと場合分けを含めて保存）

## 解法

各位置 `i` について、色 `C[i]` と異なる色の点への最短距離を求める。

左側の候補と右側の候補をそれぞれ求め、最小値を答えとする。各方向を１回ずつ走査して **O(N)** で計算する。

今回の実装では、走査済みの位置から**直近の異なる２色**を `c1` と `c2` という `(色, インデックス)` のペアで管理する。

- 現在の色が `c1` と一致する場合、`c2` を候補にする（逆も同様）。
- 現在の色が両方と異なる場合、２つの候補のうち現在位置に近いものを使い、遠い方の色の記録を現在の色で置き換える。
- 左から右へ走査した後、`c1, c2` を初期化して右から左へ走査し、`chmin` で答えを更新する。

２つの保持位置は常に異なる色で、それより前（逆向きでは後）にある同じ色の候補は新しい同色の位置に距離で負ける。そのため、直近の２種類を保持すれば十分。

## 計算量

- 時間: **O(N)**（左右に各１回走査）
- 空間: **O(N)**（`C` と `ans`）

## コンテスト中の振り返り

> 場合分けをしすぎたせいで複雑になってしまい、初期実装ではサンプルが通りませんでした。ただ、コードの後半を消して前半のどこがうまく動かないのかを特定する手法で場合分けの考慮漏れに気づきました。

最終的にはコンテスト中に **19:23 でAC**。本番提出のWAは０回。

良かった点は、動作しないときに**処理を部分的に無効化して不具合を局所化した**こと。一方で、初めから保持する状態と不変条件を言語化できれば、分岐を減らして実装をもっと短くできる。

## 補足：より簡潔な実装の方向性（ACコードは変更しない）

この問題では、左から走査するとき `C[i] != C[i-1]` なら左側の最短距離は１、同色なら `前位置の左側最短距離 + 1` と考えることもできる。右側も対称に処理できる。これは復習時に考えられる別解であり、保存した `main.cpp` はコンテスト中の実装そのまま。
