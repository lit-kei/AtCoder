# ABC485 D — ABC|ABC|ABC

- [問題文](https://atcoder.jp/contests/abc485/tasks/abc485_d)
- 結果: **AC / 400点 / 68:17 / WA 3回**
- [main.cpp](main.cpp): 第4版（最終AC）。途中のWA版は保存せず、変更点を本ファイルに記録する。

## 問題と方針

`A`, `B`, `C` からなる文字列を2か所で切り、3つの区間のそれぞれが3文字すべてを含む分割数を求める。

1番目の区間の末尾の **0-indexed 添字 `i`** と、2番目の区間の末尾の **0-indexed 添字 `j`** を使うと、区間はそれぞれ `[0,i+1)`、`[i+1,j+1)`、`[j+1,N)`。

- `k0` は先頭が3文字そろう最初の末尾添字。したがって `i >= k0` が必要。
- `k1` は末尾が3文字そろう最後の `j`。すなわち `[k1+1,N)` は条件を満たし、`j <= k1` が必要。
- 文字別累積和 `ruiA/ruiB/ruiC` を用いて各区間の含有判定を O(1) で行う。
- `i` を固定して、中央に3文字がそろう最小の `j = sj` を二分探索。可能な `j` は `sj..k1` なので、個数は `k1-sj+1`。

`j <= k1` の範囲では末尾 `[j+1,N)` に3文字が必ず存在し、中央区間 `[i+1,j+1)` が3文字を含むかだけが `j` に対して単調（false → true）になる。このため二分探索が成立する。

| 第4版 | **AC** | 早期終了を、**`[i+1,k1+1)` の中央候補区間に A/B/C がそろっているか**で直接判定するよう修正。 |

### 残るWAの根本原因：二分探索前の存在判定

第3版まで、各 `i` に対するループの打ち切り条件は次のものだった。

```cpp
if (A - ruiA[i+1] <= 1 ||
    B - ruiB[i+1] <= 1 ||
    C - ruiC[i+1] <= 1) break;
```

これは「`i` の右側に、各文字が少なくとも2個残っているか」を調べるだけで、**末尾に割り当てなければならない文字を除いた中央部分に3文字あることは保証しない**。

そのまま `small(i)` を呼ぶと、中央に3文字がそろう `j <= k1` が存在しないにもかかわらず、`ok=k1` を有効な境界として扱ってしまう。そうすると `sj=k1` が返り、存在しない分割を `k1-sj+1=1` と数える場合がある。

最終版では以下のように変更した。

```cpp
if (ruiA[k1+1] - ruiA[i+1] < 1 ||
    ruiB[k1+1] - ruiB[i+1] < 1 ||
    ruiC[k1+1] - ruiC[i+1] < 1) {
    break;
}
```

これは、`j` に選べる最大の位置 `k1` まで中央区間を広げた場合にも3文字がそろうかを検証している。ここで不成立なら、どの `j <= k1` も不成立なので打ち切ってよい。

さらに `i` を右に動かすと中央の候補区間は短くなるため、いったん不成立なら以降も不成立であり、`break` してよい。

**ポイント:** 「解が存在することを保証できる境界」`ok` を二分探索に渡す前に、`check(i,k1)` が成立することを確かめる必要があった。

## 計算量

- 時間: **O(N log N)** — 左端 `i` ごとに右端 `j` を二分探索
- 空間: **O(N)** — 文字列と3本の累積和

## 振り返り・今後の注意

- 最初の修正で区間を `[i+1,n+1)` と捉え直したことにより、8WA → 3WA まで改善した。
- 第3版の長さチェックは、**条件が成立する可能性のある区間を直接確認する**ことの代替にはならなかった。
- 二分探索の不変条件（`ng` は不成立、`ok` は成立）を明示し、`ok` の初期値が真であることを保証する。区間端点を図示するとオフバイワンを減らせる。
- 最終修正で有効な `j` が存在しないケースを早期に除外でき、コンテスト中にACした。
