# Educational DP Contest P — Independent Set

- 問題: https://atcoder.jp/contests/dp/tasks/dp_p
- 結果: AC（本人報告）
- 言語: C++ / AtCoder Library `modint1000000007`
- 方針: 非再帰DFSの順序を逆転させた木DP

## 状態と遷移

木を頂点 0 で根付き木とし、頂点 `v` の部分木において
- `dpB[v]`: `v` を黒く塗る場合の有効な塗り分け数
- `dpW[v]`: `v` を白く塗る場合の有効な塗り分け数

黒同士の隣接は禁止されるため、子 `x` について

```math
dpB[v] = \prod_{x\in child(v)} dpW[x]
```

```math
dpW[v] = \prod_{x\in child(v)} (dpW[x] + dpB[x])
```

葉では双方 1。答えは `dpB[0] + dpW[0]`（mod 1,000,000,007）。

## 計算順序と証明

「ある頂点を計算するとき、その頂点以下はすべて計算済みにしたい」ため、子を親より先に計算する必要がある。
DFSで頂点をスタックから取り出して `order` に追加すると、各子は必ずその親より後に現れる。従って `order` を逆順に走査すれば、各子が親より先に処理される。

本人による背理法の説明：
「逆順にして子が親より後だとすると、元の順序では子が親より先に探索されていることになりおかしい」。

## デバッグで修正した点

1. `child[p].push_back(x)` ではなく `child[v].push_back(x)`。最初の `p=-1` は範囲外アクセスになる。
2. `vector<ll> dfs(N)` は N 個の 0 で初期化されるので、`push_back` で収集する場合は空配列にする。
3. DFSの訪問順（親→子）のままDPせず、逆順（子→親）にする。

## 計算量

- 時間: `O(N)`（各頂点・辺を定数回処理）
- 空間: `O(N)`（隣接リスト、子リスト、DFS順序、DP、スタック）

## 学んだこと

木DPは「各状態の意味」「子の答えから親の答えへの遷移」「子から親への計算順序」を分けて考えると実装しやすい。非再帰DFSでも逆順を使えば再帰後処理と同じ順序を実現できる。
