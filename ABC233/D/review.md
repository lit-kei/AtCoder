# ABC233 D — Count Interval

- 問題: https://atcoder.jp/contests/abc233/tasks/abc233_d
- 結果: **AC**（本人確認）
- コード: [main.cpp](main.cpp)
- 手法: 累積和 + map による出現回数カウント

## 方針

当初「尺取り法か」と考えたが、A に負の値があり得るので通常の尺取り法の単調性が使えないと判断。
累積和 `rui[r] = A[0]+...+A[r-1]` を考え、区間 [l,r) の和が K であることを

```math
rui[r] - rui[l] = K
\iff rui[r] = K + rui[l]
```

に変形する。

## 実装

`map<ll,ll> x` には、これまでに見た左端 l ごとに「将来の累積和で一致してほしい値」`K+rui[l]` の出現数を格納する。

各右端 r で
1. `ans += x[rui[r]]` として、条件を満たす過去の左端の個数を加算する。
2. `x[K+rui[r]]++` として、現在の位置を将来の左端候補として登録する。

照会してから登録する順序により、l=r の空区間を数えない。特に K=0 の場合に重要。

## 計算量

累積和 O(N)、各 map 操作 O(log N)、計 N+1 回。
時間 **O(N log N)**、空間 **O(N)**。

## 自力とヒント

**自力**: 負数を見て尺取り法を避けたこと、累積和への帰着、`rui[r] = K+rui[l]` の導出、`map` に「将来の一致希望値」を蓄える発想。

**対話でのヒント**: 最初は一致を見つけたとき別の map のカウントを増やしていた。過去の左端の候補数 `x[rui[r]]` を答えに加算すればよいと指摘され、本人が最終実装にしてAC。

## 振り返り

「累積和とハッシュ/平衡木で頻度を管理する」典型を具体的な式から導いた。照会・登録の順序、K=0 と同じ累積和が続く場合の多重度に注意。
