# ABC217 D — Cutting Woods

## 発想と考察

当初「Union-Findの逆？」から考え、切断位置を管理して二分探索する方法を検討した。

- `vector` は二分探索こそ高速だが、昇順を維持した途中挿入には要素移動が必要で、最悪 O(Q)。
- 長さ L は大きく、`vector<bool>(L+1)` による密な管理も好ましくない。
- 結局、**座標そのものを順序付き集合 `set` に保存**する方針へ転換した。
- 両端 0 と L は番兵として最初から保存する。

切断操作では `cut.insert(x)`。長さの問い合わせでは `cut.upper_bound(x)` により右境界を取得し、その一つ前を左境界として差を答える。

```cpp
auto it = cut.upper_bound(x);
cout << *it - *prev(it) << "\n";
```

## 計算量

各操作 O(log Q)、全体 **O(Q log Q)**、空間 **O(Q)**。

`std::upper_bound(cut.begin(), cut.end(), x)` は `set` のイテレータ移動に線形時間がかかり得るので、対数時間を保証する `cut.upper_bound(x)` を使う。

## 重要な注意点

元のAC提出は

```cpp
cout << *it - *(--it) << "\n";
```

となっている。しかし、`-` の左右の評価順序は未規定で、同じイテレータ `it` の変更と読み出しが順序付けられていないため **未定義動作**。ACは正しさの保証にはならない。上記の `prev(it)` を使う修正が安全。
