# ABC222 D — Between Two Arrays

- 問題: https://atcoder.jp/contests/abc222/tasks/abc222_d
- 結果: **自力AC**（本人確認）
- 時間計算量: **O(NV)**（`V = B[N-1] <= 3000`）
- 空間計算量: **O(V)**（DP用配列。入力配列を含めると O(N+V)）

## 方針

`dp[j]` = これまでに処理した長さの条件を満たす数列で、最後の値が `j` であるものの数。

初期化は `A[0] <= j <= B[0]` に対し `dp[j]=1`。

数列 `C` は単調非減少なので、次の数を `j` にするには直前の値 `k <= j` が必要。よって

```text
next[j] = sum(dp[k], k=0..j)  (A[i] <= j <= B[i])
next[j] = 0                  (それ以外)
```

となる。各 `j` について和を毎回計算すると O(NV²) になるが、左から累積和 `ruiseki` を管理すれば O(NV) にできる。

各行は直前のDPしか参照しないため、2次元配列ではなく `dp` と `next` の2本で管理する。各値の計算は `modint998244353` を用いる。

## 自力で考えたこと

- 2次元DPのメモリ使用量を確認（3000² 個の long long なら約72MB）。
- 最後に追加した値を状態として持つDPを設計。
- 遷移に累積和を導入し、配列の総和計算を高速化。
- 新旧状態が混ざらないように `dp` と `next` を分離し、計算後に移し替えた。

## 実装上の改善

- `next` と `dp` の全コピーの代わりに `swap` も利用できる（ただし作業配列のクリアを適切に行う）。
- この問題では昇順走査と旧値を保持する累積和を組み合わせれば1配列での更新も可能。
- `B[N-1]` を最大の状態値として使えるのは、Bが単調非減少であるため。
