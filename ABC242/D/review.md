# ABC242 D — ABC Transform

- 問題: https://atcoder.jp/contests/abc242/tasks/abc242_d
- 結果: **完全自力・一発AC**（本人確認）
- コード: [main.cpp](main.cpp)
- 手法: 二進数による変換経路の逆算、mod 3

## 着想

文字列は変換するたびに長さが2倍になる。t 回後は元の1文字に由来する長さ 2^t のブロックが並ぶ。
0-indexedの位置 k が属する元の文字は `floor(k/2^t)` 番目。ブロック内の移動経路は k の下位 t ビットで表される。

本人の最初の考察: 「2^tで割ればもともと何番目だったかわかる？ 2進数が大事？」

## 文字の変換

A,B,Cをそれぞれ0,1,2とする。各変換で左の子は元の文字+1、右の子は元の文字+2（mod 3）。
したがって、t回の変換で右を選んだ回数を cnt とすれば、答えは

```text
(S[index] - 'A' + t + cnt) mod 3
```

となる。右を選んだ回数は k の下位 t ビットの popcount と一致する。

## 本人の実装

`n` を 2 倍ずつ増やし、kより大きくなるかt回終わるまで処理する。k<nなら元の添字は0、そうでなければk/nとなる。
もう1つの while ループで t 回まで k の下位ビットを調べ、1の個数 `cnt` を加算する。
`help()` で値を3で割った余りから文字に戻す。

## 計算量

入力文字列長を L、各クエリ位置の最大値を K とすると、各クエリ O(log K+1)（long longでは高々約60回）。
全体で時間 **O(L + Q(log K+1))**、格納する文字列の空間 **O(L)**。

## より簡潔な実装

t回まで下位ビットを数えて k を2で割れば、カウント終了時の k がそのまま元の文字の添字になる。

```cpp
ll cnt = 0;
while (t > 0 && k > 0) {
    cnt += k % 2;
    k /= 2;
    t--;
}
```

ただしこの形で t 自体を減らす場合、出力の `+ t` には元の t を別に保存して使う必要がある。本人のコードでは別変数 `tmp` で残回数を管理しているため、元の t がそのまま使える。

## 自力と振り返り

**完全自力・一発AC**。元の位置を2の累乗で求める考察、二進数で右への分岐数を数える考察、mod 3の算術化から実装まで自力。AC後に2ループを1ループへ整理できると確認した。
