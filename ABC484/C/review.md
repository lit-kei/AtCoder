## 着眼点

配列 `A` と `B` の異なる添字の最小値を `first`、最大値を `end` とする。一致していれば即 `Yes`。
1要素を別の位置へ移動する場合を、左方向と右方向に分けて調べる。
全要素を実際に移動した配列を構築する代わりに、移動が及ぼす区間の等式を直接確認する。

## 左方向への移動

`k` 番目の要素を `first` に持ってくる場合、`first <= i < k` について
`A[i] == B[i+1]`、さらに `A[k] == B[first]` が必要。
`k >= end` を満たす候補まで走査し、各条件を確認する。一度ずれが生じると、その先の候補はこの方向では成立しないため打ち切る。

## 右方向への移動

`k` 番目の要素を `end` へ持っていく場合、`k < i <= end` について
`A[i] == B[i-1]`、さらに `A[k] == B[end]` が必要。
`k <= first` の候補まで逆順に走査する。

## 計算量

- 時間計算量: `O(N)`（差異区間の検出と両方向の走査）
- 空間計算量: `O(N)`（入力配列）、追加領域は `O(1)`

## コードレビュー

- 差異区間の両端を求めてから、移動による添字の対応関係を検査する発想がよい。
- 配列のコピーや挿入・削除をせず線形時間で解いている。
- `end` は `last` や `right` などの名前にすると明確。
- `dfor(i,end+1,1)` は `i=end,...,1` の意味なので境界の確認が重要。
- 移動させる要素の候補位置が `first/end` の外まで伸びる点を考慮している。
