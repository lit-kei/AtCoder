# ABC484 F — Make them monochrome

- [問題](https://atcoder.jp/contests/abc484/tasks/abc484_f)
- 結果：コンテスト後にAC（本人報告）
- 難易度：水Diff（本人報告）
- 実装：AtCoder Library のセグメント木

## 着想

区間の値がすべて等しいかを判定するため、各区間の情報を「全要素が同じ値ならその値、異なる値が混在するなら 0」で表す。
タイプ1のクエリでは一点更新、タイプ2では指定区間を結合して 0 でなければ Yes とする。

## 自作モノイド

```cpp
ll op(ll a, ll b) {
    if (a == 0 || b == 0) return 0;
    if (a == -1) return b;
    if (b == -1) return a;
    if (a == b) return a;
    return 0;
}

ll e() {
    return -1;
}
```

意味：
- 通常の正の整数 x：区間の要素がすべて x
- 0：異なる値が混在
- -1：空区間を表す単位元

0 が一度現れたら、それ以降結合しても混在状態のまま。通常の値が一致すればその値を維持し、異なれば 0 を返す。

### -1 を単位元にした理由

**本人の考察：『-1にすれば単位元として満たすべき性質が満たされると考えた』。**

```math
\mathrm{op}(a,-1)=\mathrm{op}(-1,a)=a
```

0 と -1 が通常の入力値として現れない前提で、区間の要約結果を結合する演算となるため結合律も満たす。

## 計算量

- 初期化：セグ木を空で作り N 回 set するため O(N log N)
- 各クエリ：一点更新・区間取得ともに O(log N)
- 全体：O((N+Q) log N)、空間 O(N)

初期配列から直接セグ木を構築すれば初期化は O(N) に改善できる。

## コードレビュー

- E問題では加算モノイドを利用したが、F問題では判定に合わせて独自の op と e を設計できた。
- YES/NO マクロ自体が改行するため、その後の cout << "\n"; は不要。
- 0 や -1 が入力値として登場する一般の場合は、状態と値を別々に管理するなど設計を変更する必要がある。

## 振り返り

**セグメント木は区間を分割する仕組みであり、何を保持しどう結合するかを自分で決めることが重要。**
水DiffのF問題を、E問題で学んだ直後のセグメント木で解くことができた。
