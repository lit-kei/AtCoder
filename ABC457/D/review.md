# ABC457 D — Raise Minimum

- [問題](https://atcoder.jp/contests/abc457/tasks/abc457_d)
- コンテスト: ABC457（2026-05-09）
- 配点: 400点
- 結果: AC（オーバーフローの修正後）
- 解法: 答えで二分探索

## 解法の発想

操作を直接シミュレーションするのではなく、**数列の最小値を少なくとも `x` にできるか**を判定する。

添字 `i`（0-indexed）の要素は1回の操作で `i+1` 増えるため、必要な最小操作回数は

```math
c_i(x)=\max\left(0,\left\lceil\frac{x-A_i}{i+1}\right\rceil\right)
```

となる。各要素の操作は独立なので、

```math
f(x)=\sum_{i=0}^{N-1}c_i(x)
```

が `K` 以下なら実現可能。

`x` が増えるほど `f(x)` は減少しないため、判定の真偽には単調性がある。この性質を用いて、達成可能な最大の `x` を二分探索する。

## 実装

- `ok=0`: 必ず実現できる下限（制約より `A_i>=1`）。
- `ng=A[0]+K+1`: 先頭要素は1回につき1しか増えず、`K` 回ではこの値に届かないため、必ず実現不可能な上限。
- `check(x)`: 必要操作回数を全要素で計算し、合計が `K` 以下かを判定。

切り上げ除算は、`d=x-A[i]>0` の場合に `(d+i)/(i+1)` で表せる。元コードでは `max(...,0LL)` を併用している。

## 発見・修正したバグ：整数オーバーフロー

当初は必要操作回数を全要素について無条件に足していた。

```cpp
cnt += max((d + i) / (i + 1), 0LL);
```

`N<=2*10^5`, `A_i,K<=10^18` なので、二分探索中に検査する値によっては、必要操作回数の合計が `long long` の上限を超える。符号付き整数オーバーフローは C++ では未定義動作であり、判定結果が壊れうる。

**修正：`cnt>K` になった時点で `false` を返す。**

```cpp
bool check(ll n) {
    ll cnt = 0;
    rep(i, N) {
        ll d = n - A[i];
        cnt += max((d + i) / (i + 1), 0LL);
        if (cnt > K) return false;
    }
    return true;
}
```

加算直前には常に `cnt<=K<=10^18` であり、1要素の追加操作回数も今回の探索範囲では `long long` の範囲内なので、途中終了することで合計のオーバーフローも防げる。

## 計算量

- 判定1回: `O(N)`
- 二分探索: `O(log(A_1+K))`
- 全体: **`O(N log(A_1+K))`**
- 追加空間: **`O(1)`**（入力配列を除く）

## コード評価

**良かった点**
- 「最小値の最大化」を「目標値以上にできるか」という単調な判定に言い換えられている。
- 要素ごとの必要操作回数を切り上げ除算で正確に算出し、無駄なシミュレーションをしていない。
- `ok` と `ng` の境界が実現可能・不可能に対応しており、二分探索の方向と更新も正しい。
- 計算量は制約に十分間に合う。

**改善点**
- `K` 自体が `long long` に収まっていても、判定途中の**累積値が収まるとは限らない**。
- 合計が閾値を超えた時点で判定を打ち切ると、オーバーフロー防止と高速化を両立できる。

## 学んだこと

**二分探索の判定関数では、答えの範囲だけでなく、途中で計算する値の最大値も確認する。** 特に「合計が `K` 以下か」だけを知りたいなら、`K` を超えた時点で早期終了する設計が有効。

二分探索の発想や単調性の扱いは正しく、主な修正点は整数型の安全性だった。
