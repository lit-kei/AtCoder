# ABC486 D — モンスターのレベルと最小消費体力

- [問題文](https://atcoder.jp/contests/abc486/tasks/abc486_d)
- [AC提出](https://atcoder.jp/contests/abc486/submissions/81141146)
- **結果：AC / 400点 / 25:27 / WAなし**
- [main.cpp](main.cpp)：本人提供のコンテスト中ACコード

## 問題

高橋君は最初レベル1。モンスターを順番に見ていき、そのレベル `L_i` が現在のレベル以下なら、戦うかどうかを選べる。戦えば体力を `P_i` 消費し、レベルが1上がる。最後の `N` 番目のモンスターを倒すために必要な消費体力の合計を最小化する。倒せない場合は `-1`。

## 発想：レベルではなく倒した個数でDP

本人の実装前メモ：

> Nちっちゃ  
> O(N^2)とか？  
> DPだ  
> レベルが高々Nだから、二次元DPを作ればよい。

戦闘でレベルは1ずつ上がるので、「現在のレベル」はそれまでに倒したモンスター数 `j` で一意に決まる（レベル `j+1`）。

`dp[i][j]` = 最初の `i` 体の処理後、`j` 体を倒している状態に到達するための **最小消費体力** とする。到達不能は `INF`。

初期値：

```cpp
dp[0][0] = 0;
```

各モンスター `i` について：

1. **戦わない：** `dp[i][j] = min(dp[i][j], dp[i-1][j])`
2. **戦う：** 現在レベル `j+1` が `L_i` 以上なら
   `dp[i][j+1] = min(dp[i][j+1], dp[i-1][j] + P_i)`

元コードは `l--` により、戦える条件を `j >= l` としている。

`i == N` のとき、戦える各状態について `dp[N-1][j]+P_N` の最小値を `ans` に入れる。戦える状態がなければ `-1` を出力する。

## 正当性

処理済み数 `i` と撃破数 `j` が同じ2状態では、現在のレベルも同じなので、**これから戦えるモンスターの集合・選択肢は同じ**である。したがって消費体力の小さい方だけ残せば、最適解を失わない。

各状態から「戦わない」「レベル条件を満たすなら戦う」という全選択肢を遷移させているため、最後の敵を倒す全ての実行可能な戦略から最小消費体力を求められる。

重要：`dp[i][j]` は「残り体力」ではなく「累積消費体力」の最小値。体力の初期上限等を状態に含める必要はない。

## 計算量

制約 `N <= 6000` より、各 `i` に対して `j=0..N` を走査する。

- 時間：**O(N²)**
- 空間：**O(N²)**（`(N+1)×(N+1)` の `long long` DP表）

`N=6000` ではDP本体だけで約288MBを使用する。実行環境のメモリ制限に注意。

## コードレビュー・改善点

- `INF` の状態から遷移しないので、到達不能値に加算しない安全な実装。
- `P_i <= 10^9`、`N <= 6000` なので合計は最大でも `6×10^{12}` 程度。 `long long` で十分。
- `dp[i][j+1]` は `j=N` だと範囲外になるが、`i<=N` で `i-1` 体までしか処理していないため、実際に到達可能な `j` は `j<=i-1<=N-1`。そのためこのコードでは範囲外アクセスは発生しない。
- **改善案：** `dp[j]` を撃破数 `j` の一次元配列に圧縮できる。各モンスターについて `j` を降順に走査して戦う遷移を更新すると、同じモンスターを二度使わず **O(N)** 空間にできる。ACコード自体は保持する。
- 最後の敵に対しては、選べる最小コストをその場で `ans` に反映する実装。可否判定は `ok` で分かりやすい。

## 振り返り

**Cが7:09、Dが25:27でAC。** Cから18分18秒で400点のD問題をWAなしで解き切った。探索条件が「これまでに何体倒したか」だけで決まることに着目し、DPの状態数を `O(N²)` に抑えたのが核心。
