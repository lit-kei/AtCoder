# ABC220 D — FG operation

- 問題: https://atcoder.jp/contests/abc220/tasks/abc220_d
- 結果: **AC**（本人確認）
- 時間計算量: **O(10N) = O(N)**
- 空間計算量: DPのみ **O(10) = O(1)**、入力配列を含めると **O(N)**

## 発想

各隣接段階で F（加算）または G（乗算）を選ぶ全探索は `2^(N-1)` 通り。
しかし、以降の結果を計算するにはこれまでの演算履歴は必要なく、**現在の値の10で割った余りだけ**分かれば十分。

自力の考察メモ:
> %10は最後にやってもいい。  
> 2^10000はどう考えても間に合わないので、いい方法がありそう。  
> 1の位と、次の値がわかってさえいれば計算できる→DPでおけ

## DPの定義・遷移

`dp[r]`: 処理済みの数から、計算結果が `r` (mod 10) となる演算列の数。

初期条件: `dp[A[0]] = 1`。

次の入力を `a` とすると、各 `r = 0..9` に対して

```cpp
next[(r + a) % 10] += dp[r];
next[(r * a) % 10] += dp[r];
```

同じ余りへ両方の演算が遷移しても、操作選択が2通りあるため両方を加算する。
法 `998244353` の演算に `atcoder::modint998244353` を用いる。
`next` 相当の `add` を毎回リセットすることで、新旧のDP状態を混ぜない。
